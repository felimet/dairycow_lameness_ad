# Implementation choices where the Methods description admits more than one reading, and evidence boundaries of each analysis

*Traditional Chinese version: [IMPLEMENTATION_NOTES.zh-TW.md](IMPLEMENTATION_NOTES.zh-TW.md)*

Settings are fixed in `cowlame/config.py` and are logged at the start of a run by every script except `scripts/check_window_lists.py`. No setting is tuned toward a published value. Numbers obtained from the data are in `results/REPORT.md` (cohort section and comparison table) and are not repeated here.

1. **Analysis cohort.** The aligned rows of `window_manifest_maskfirst.csv` define the evaluable passes; the counts obtained (windows, passes, cows, consensus scores, crowding strata) are written by `scripts/make_cohort.py` to `results/cohort.json` and summarized in `results/REPORT.md`. The manuscript reports one pass fewer and one fewer high-crowding pass; no pass is dropped to match those counts, and the difference is tabulated in the report. Every selected modality is validated against its own PNGs when the tensor cache is built.
2. **Missing identity.** Passes with an empty cow ID form one `GroupKFold` group named `unknown`. `--unknown-cow-policy per-pass` treats each such pass as its own group and is offered as a sensitivity analysis written to a separate output directory. Cow IDs remain strings exactly as stored; no numeric reordering is introduced. Folds are constructed on passes with `GroupKFold(5)` and no shuffling, and every fold asserts disjoint cow groups between training and test.
3. **Precomputed energy images.** The analysis reads the precomputed `matlab_ei/` images named in the manifest; the archived PNGs are used as-is for every detection result. Their window provenance (hop, morphology) is not encoded in the final PNGs. For the 72 passes with mask metadata, the number of archived energy-image windows equals the length of `keep_windows_w30` in all 72, of `keep_windows_gated` in 32 and of `keep_windows` in 30; `window_size` equals the recorded stride period in 69 of 72; the window hop is not recorded in the metadata (`results/window_lists.json`, written by `scripts/check_window_lists.py`). The energy-image cross-check (`docs/EI_XCHECK.md`) therefore iterates `keep_windows_w30` by default (`--window-list`) and documents the ordinal correspondence it supports. Per-window agreement on pass 001/01 is reported for both lists in `docs/EI_XCHECK.md`.
4. **Crop and resize.** The leg-region crop keeps rows `floor(H*(1-alpha)):H` with `alpha = 0.45` applied to each PNG, followed by Pillow bilinear resize (with its resampling antialiasing) to 128 x 128; the crop (99 x 318 for GEI/CGI/FDEI from 220 x 318, or 81 x 382 for HEI from 180 x 382) is resized anisotropically, so the leg-region aspect ratio is not preserved; intensities are 8-bit values divided by 255. No augmentation and no anatomical crop estimation. HEI uses `hei_comb6_path`; GEI/FDEI stay single-channel except at pretrained-backbone inputs, where the channel is replicated to three and ImageNet-normalized.
5. **Subspace unit.** The Subspace paragraph of the Methods is taken as governing over the generic window-training statement: PCA is fitted to one raw pass-mean image per normal training pass and one mean image per test pass is scored by the mean-squared residual after PCA projection. At most 30 components (or the number of normal training passes minus one), full SVD, no whitening. The concatenated fusion applies the same operation to the concatenated GEI + CGI + FDEI pass means, without modality weighting or rescaling. This makes Subspace the one detector whose pass score is not the mean of its window scores: PatchCore, ConvAE and STFPM score every window of a test pass and average those window scores (`evaluate.aggregate`), whereas Subspace both fits and scores the pass-mean image (`cowlame/evaluate.py`, `cross_validate`), so a Subspace pass score is the reconstruction residual of the pass mean image and not the mean of that pass's window residuals. The two aggregations are not equivalent, because averaging the silhouette windows before the PCA projection is not the same operation as averaging their residuals afterwards.
6. **PatchCore blocks and distances.** "Up to the seventh block" is read as torchvision `mobilenet_v3_large(IMAGENET1K_V1).features[:7]` (modules 0 to 6, including the stem), giving 40 channels at stride 8; `--patchcore-blocks` exposes this reading and also sets the STFPM teacher (item 8). Patch descriptors are the raw feature vectors compared by Euclidean nearest-neighbour distance; feature normalization is applied only where the Methods state it (STFPM). Memory-bank indices are sampled without replacement with NumPy `default_rng(42)`; a new generator seeded with the same value 42 is created for every fold (folds are not given distinct seeds, so folds differ only through their normal-patch population), bank size `floor(10% of normal patches)`, minimum one. No greedy coreset, neighbourhood aggregation, multiscale concatenation, reweighting or smoothing is added. Frozen features are extracted once before splitting because extraction has no fitted state; each bank sees only normal training windows.
7. **ConvAE decoder.** Four 4 x 4, stride-2, padding-1 transpose convolutions map 128 -> 128 -> 64 -> 32 -> input channels; BatchNorm/ReLU follow the first three and Sigmoid the last. The encoder is input -> 32 -> 64 -> 128 -> 128. Convolution biases use PyTorch defaults. The final epoch (40) is always the evaluated model.
8. **STFPM student.** The Methods give the student only by its depth and channel rule; this implementation uses Conv2d(3, 20, 3, stride 2, padding 1), ReLU; Conv2d(20, 20, 3, 2, 1), ReLU; Conv2d(20, 20, 3, 2, 1), ReLU; Conv2d(20, 40, 3, 1, 1), with no student BatchNorm and no final activation. Teacher and student receive the same ImageNet-normalized input. Channel-normalized squared differences are averaged over all elements for training; the channel-vector Euclidean distance is averaged spatially for scoring. Native distance maps are enlarged by nearest interpolation, which preserves their mean. The teacher is the same `features[:patchcore_blocks]` slice as PatchCore, so `--patchcore-blocks` changes both detectors and the number of stride-2 student layers, which is derived from the teacher stride.
9. **Training and numerics.** Adam with lr 0.001 and default betas/epsilon, batch 64, 40 epochs, no scheduler, no early stopping and no checkpoint selection. Training uses CUDA AMP; scoring is float32. All random components start from seed 42; cuDNN deterministic mode is enabled, benchmarking is disabled and matmul TF32 is disabled; cuDNN convolution TF32 is left at the PyTorch default (enabled), so float32 convolutions in feature extraction and scoring may run in TF32 on GPUs that support it. GPU/CPU reductions, AMP, library versions and batch normalization can shift results between environments; the size of such shifts is not treated as a verified tolerance.
10. **Curves and fold metrics.** Held-out AUROC is evaluated after every epoch for diagnosis only; no training or parameter choice uses it. Each metric has its own t-based interval across the five fold values (df = 4), without clipping at 0 or 1. AUPRC is average precision. Max F1 uses the actual precision-recall thresholds and takes the first maximizer (lowest tied threshold). The pooled threshold is an evaluation-set oracle, not a deployed operating point.
11. **Pooled inference.** Raw scores from separately fitted folds are pooled as described in the Methods; common score calibration across folds is not established. The label-permutation test uses 10,000 permutations, seed 42, pass-level exchangeability on fixed out-of-fold scores, and reports both `count/B` and `(count+1)/(B+1)`. It does not retrain normal-only models after permuting labels, does not preserve within-cow correlation, and does not correct for choosing the best detector/modality configuration; it should not be read as a selection-corrected significance test of the full learning procedure. Rank-sum AUROC with average ranks for ties is identical to recomputing ROC AUC on each permuted label vector.
12. **Severity and crowding.** Detected counts use the pooled oracle threshold and a one-sided binomial comparison with the marginal flagging rate of the same cohort. These are descriptive: the baseline is estimated and outcomes within cows need not be independent. Crowding strata are unadjusted pooled comparisons, not causal estimates of a crowding effect.
13. **Per-cow normalization.** Within-cow z-scores use the population standard deviation (ddof = 0) of a cow's out-of-fold scores; single-pass cows keep raw scores and zero-variance multi-pass cows receive zero. Scores are rounded to 12 decimals so that the exact +/-1 ties produced by two-pass cows survive a CSV round trip (without rounding, floating-point noise broke ties and changed the AUROC between the in-memory and the deposited values). The procedure mixes scales and is transductive; it is the sensitivity analysis described in the Methods, not a calibrated deployment method. The `unknown` group follows the selected missing-ID policy.
14. **Reference values.** `cowlame/manuscript_reference.json` holds the manuscript values used for comparison, each block labelled by source. Exact text values: the PatchCore/Subspace AUROC grids (leg and full), the PatchCore-CGI interval, AUPRC, max-F1, permutation statistics, Spearman rho and per-severity median scores, detected counts, crowding strata, the analysis-pass count, segmentation Table 1 (validation split, final epoch) and the retained checkpoint's logged validation and test-split metrics from the Results. Read from a figure (approximate, about +/-0.01): the ConvAE and STFPM AUROCs. Stated only approximately in the text: the HEI permutation band, late-fusion and per-cow AUROCs. The manuscript's Evaluation protocol identifies every reported point estimate as the metric on the pooled out-of-fold scores and every reported 95% interval as the t interval across the five folds, so each manuscript AUROC is compared against both the pooled and the fold-mean value obtained here, and the pooled row is the like-for-like one. Not reported: the Subspace mild detected count; that row shows NA. The asymmetric published PatchCore interval is copied literally.
15. **Optional analyses.** PatchCore distance evaluation is inexpensive enough to also run the GEI + CGI + FDEI patch-feature concatenation (120 channels at matched patch locations) in addition to the Subspace concatenation. Each modality is independently ImageNet-normalized before frozen feature extraction; no feature weighting or joint normalization is added. Figure data are deposited as CSV; styled figures are not generated.
16. **Hardware and environment.** The manuscript lists GTX 1080 8 GB, CUDA 11.8 and PyTorch 2.5.1. The runs deposited here used an RTX 5070 with the CUDA 12.8 PyTorch build; the installed versions are pinned verbatim in `requirements.txt` and `environment.yml`, and the GPU/version strings are recorded in `results/runtime_main.json`. On Windows, `conda run` required an ASCII temporary folder inside the `cowlame` environment because its activation batch file could not handle a non-ASCII repository path.
17. **Upstream segmentation.** The archived `args.yaml` records `device: 0,1`, `split: val`, `tracker: botsort.yaml`, 100 epochs with patience 25 and disk caching; these training-time settings do not by themselves establish the single-GPU or ByteTrack inference configuration used downstream. The archived inference notebook performs single-image prediction and contains no tracking call. The dataset YAML carries an obsolete absolute Linux `path:`; only a repository-local copy is remapped to the current absolute dataset root. Both `val` and `test` are evaluated independently (`docs/SEG_XCHECK.md`), with all outputs and caches confined to the repository.
18. **Energy-image reference implementation.** `cowlame/energy_images.py` implements Eq. (1) to (5) from binary silhouettes: centroid-aligned GEI, equal-index temporal thirds for CGI, FDEI as positive frame differences plus segment-peak-retained static energy (the Methods give no numerical denoising threshold; `EnergyConfig.denoise_peak_fraction` exposes the choice), and whole/front/rear union-aligned HEI with the six channel permutations. The window hop is not recorded in `mask_meta.json`; `EnergyConfig.window_step` (default 5) is an exposed assumption. Further readings taken by the code: the front/rear split of each silhouette is the midpoint of its per-frame bounding box; the travel direction (`front_direction = "auto"`) is inferred from the sign of the net centroid displacement between the first and last non-empty frames of the window and can be overridden with `--front-direction`; the first previous frame of the FDEI difference is the first frame itself (B_0 := B_1); HEI channels are rendered at 180 x 382 to match the archived HEI PNGs, GEI/CGI/FDEI at 220 x 318. The MATLAB morphology and body-proportion crop that produced the archived images are not part of these equations, so identity is not expected; agreement is quantified per window in `docs/EI_XCHECK.md`.
19. **Named deviation from the Methods text: the body-proportion crop is not reproduced.** The Methods state that the gait energy image is cropped by body proportion and scaled to 220 x 318 pixels. The reconstruction performs only the second half of that: `cowlame/energy_images.py` resizes an untrimmed union of foreground bounding boxes directly to the archived output size. For GEI, CGI and FDEI that union is taken over the centroid-aligned per-frame boxes (`align_centroids`) and resized to `EnergyConfig.image_hw` = 220 x 318; HEI is not centroid-aligned, so its whole/front/rear channels are taken over the raw per-frame boxes of the window, that is the union along the animal's trajectory, and resized to `EnergyConfig.hei_hw` = 180 x 382. No body-proportion crop is applied, because the archived metadata do not record the rule (which body landmark defines the proportion, what fraction is kept, and whether it is applied per frame or per window), and guessing one would put an unrecorded free parameter into a reference implementation. This is a deviation of the reconstruction from the published Methods, not one of the ambiguous readings listed above: a body-proportion crop changes the field of view that the fixed output size is filled from, so it rescales the silhouette inside every energy image. It may therefore contribute to the imperfect agreement between the regenerated and archived images reported in `docs/EI_XCHECK.md`, alongside the unrecorded MATLAB morphology and window hop. The detection results are unaffected: every analysis reads the archived PNGs, which already carry the original crop.
