# Methods 描述容許一種以上解讀之處的實作選擇，以及各項分析的證據邊界

*英文原版：docs/IMPLEMENTATION_NOTES.md（兩版內容不一致時以英文版為準）*

設定固定於 `cowlame/config.py`，除 `scripts/check_window_lists.py` 外，每個腳本都會在執行開始時記錄這些設定。沒有任何設定朝已發表的數值調校。由資料取得的數字置於 `results/REPORT.md` 的群體（cohort）節與比較表中，此處不重複。

1. **分析群體。** `window_manifest_maskfirst.csv` 中對齊的資料列定義可評估的通過段（pass）；所得計數（視窗、通過段、牛隻、共識評分、擁擠分層）由 `scripts/make_cohort.py` 寫入 `results/cohort.json`，並於 `results/REPORT.md` 摘要。稿件所報告的通過段數少一段，高擁擠通過段亦少一段；不為符合該等計數而剔除任何通過段，差異已在報告中列表。建立 tensor 快取時，每個選定的模態都會對照其本身的 PNG 驗證。
2. **缺失身分。** 牛隻 ID 為空的通過段構成一個名為 `unknown` 的 `GroupKFold` 群組。`--unknown-cow-policy per-pass` 將每個此類通過段視為各自獨立的群組，作為敏感度分析提供，寫入獨立的輸出目錄。牛隻 ID 維持與儲存內容完全一致的字串；不引入數值重排。摺（fold）以 `GroupKFold(5)` 於通過段上建構且不洗牌，每一摺皆斷言訓練與測試之間的牛隻群組互斥。
3. **預先計算的能量影像。** 分析讀取 manifest 中所指名、預先計算的 `matlab_ei/` 影像；每一項偵測結果皆原樣使用封存的 PNG。其視窗來源資訊（hop、形態學運算）並未編碼於最終 PNG 中。對於具有遮罩中繼資料的 72 個通過段，封存能量影像的視窗數在全部 72 段中等於 `keep_windows_w30` 的長度，在 32 段中等於 `keep_windows_gated` 的長度，在 30 段中等於 `keep_windows` 的長度；`window_size` 在 72 段中的 69 段等於所記錄的步幅週期；視窗 hop 未記錄於中繼資料中（`results/window_lists.json`，由 `scripts/check_window_lists.py` 寫出）。因此能量影像交叉檢核（`docs/EI_XCHECK.md`）預設迭代 `keep_windows_w30`（`--window-list`），並記載其所支持的序數對應關係。通過段 001/01 的逐視窗一致性在 `docs/EI_XCHECK.md` 中對兩份清單皆有報告。
4. **裁切與縮放。** 腿部裁切對每張 PNG 保留列 `floor(H*(1-alpha)):H`，其中 `alpha = 0.45`，隨後以 Pillow 雙線性縮放（含其重取樣反鋸齒）至 128 x 128；裁切結果（GEI/CGI/FDEI 由 220 x 318 裁得 99 x 318，HEI 由 180 x 382 裁得 81 x 382）以非等向方式縮放，故腿部區域的長寬比未被保留；強度為 8 位元值除以 255。無資料增強，亦無解剖學裁切估計。HEI 使用 `hei_comb6_path`；GEI/FDEI 維持單通道，惟於預訓練骨幹網路輸入處例外，該處將通道複製為三個並施以 ImageNet 正規化。
5. **Subspace 單位。** 以 Methods 的 Subspace 段落優先於一般性的視窗訓練陳述：PCA 對每個正常訓練通過段的一張原始通過段平均影像進行擬合，每個測試通過段的一張平均影像則以 PCA 投影後的均方殘差評分。最多 30 個成分（或正常訓練通過段數減一），完整 SVD，不做白化。串接融合對串接後的 GEI + CGI + FDEI 通過段平均影像施以相同操作，不做模態加權或重新縮放。這使 Subspace 成為唯一其通過段分數並非視窗分數平均值的偵測器：PatchCore、ConvAE 與 STFPM 對測試通過段的每個視窗評分並取視窗分數的平均（`evaluate.aggregate`），而 Subspace 則對通過段平均影像同時進行擬合與評分（`cowlame/evaluate.py`、`cross_validate`），因此 Subspace 的通過段分數是通過段平均影像的重建殘差，而非該通過段各視窗殘差的平均。兩種聚合方式並不等價，因為在 PCA 投影之前平均輪廓視窗，與投影之後平均其殘差，並非同一操作。
6. **PatchCore 區塊與距離。** 「至第七個區塊」解讀為 torchvision `mobilenet_v3_large(IMAGENET1K_V1).features[:7]`（模組 0 至 6，含 stem），在 stride 8 下給出 40 個通道；`--patchcore-blocks` 將此解讀外顯，並同時設定 STFPM 的教師網路（第 8 項）。Patch 描述子為原始特徵向量，以歐氏最近鄰距離比較；特徵正規化僅施加於 Methods 明述之處（STFPM）。記憶庫（memory bank）索引以 NumPy `default_rng(42)` 不放回抽樣；每一摺都建立一個以相同值 42 為種子的新產生器（各摺未給予不同種子，故各摺僅因其正常 patch 母體而異），記憶庫大小為 `floor(10% of normal patches)`，最少一個。未加入 greedy coreset、鄰域聚合、多尺度串接、重新加權或平滑。凍結特徵在切分前一次性擷取，因為擷取不含擬合狀態；每個記憶庫僅見正常訓練視窗。
7. **ConvAE 解碼器。** 四層 4 x 4、stride 2、padding 1 的轉置卷積將 128 -> 128 -> 64 -> 32 -> 輸入通道數；前三層後接 BatchNorm/ReLU，最後一層後接 Sigmoid。編碼器為輸入 -> 32 -> 64 -> 128 -> 128。卷積偏置使用 PyTorch 預設值。評估的模型一律為最後一個 epoch（40）。
8. **STFPM 學生網路。** Methods 僅以深度與通道規則給定學生網路；本實作使用 Conv2d(3, 20, 3, stride 2, padding 1), ReLU; Conv2d(20, 20, 3, 2, 1), ReLU; Conv2d(20, 20, 3, 2, 1), ReLU; Conv2d(20, 40, 3, 1, 1)，學生網路無 BatchNorm，亦無最終激活函數。教師與學生網路接收相同的 ImageNet 正規化輸入。訓練時對通道正規化後的平方差在所有元素上取平均；評分時對通道向量的歐氏距離在空間上取平均。原生距離圖以最近鄰內插放大，此操作保持其平均值不變。教師網路與 PatchCore 使用相同的 `features[:patchcore_blocks]` 切片，故 `--patchcore-blocks` 同時改變兩個偵測器，以及學生網路中 stride-2 層的數量，後者由教師網路的 stride 推得。
9. **訓練與數值。** Adam，lr 0.001，betas/epsilon 為預設值，批次大小 64，40 個 epoch，無排程器、無早停、無 checkpoint 選擇。訓練使用 CUDA AMP；評分為 float32。所有隨機成分皆自種子 42 起始；啟用 cuDNN 確定性模式，停用 benchmarking，停用 matmul TF32；cuDNN 卷積 TF32 維持 PyTorch 預設值（啟用），故特徵擷取與評分中的 float32 卷積在支援的 GPU 上可能以 TF32 執行。GPU/CPU 歸約、AMP、函式庫版本與批次正規化都可能使結果在不同環境間偏移；此類偏移的大小不視為已驗證的容差。
10. **曲線與各摺指標。** 每個 epoch 結束後評估保留集 AUROC，僅供診斷；任何訓練或參數選擇皆不使用它。每個指標各自有跨五摺數值、以 t 分布為基礎的區間（df = 4），不在 0 或 1 處截斷。AUPRC 為 average precision。最大 F1 使用實際的 precision-recall 閾值，取第一個最大化者（同分中最低的閾值）。合併閾值為評估集上的 oracle，並非部署的操作點。
11. **合併推論。** 各自獨立擬合的摺所產生的原始分數依 Methods 所述合併；未建立跨摺的共同分數校準。標籤置換檢定使用 10,000 次置換、種子 42、固定出摺（out-of-fold）分數上的通過段層級可交換性，並同時報告 `count/B` 與 `(count+1)/(B+1)`。它不在置換標籤後重新訓練僅用正常樣本的模型，不保留牛隻內相關性，也不校正選取最佳偵測器/模態組態的效應；不應將其解讀為對完整學習程序經選擇校正的顯著性檢定。以平均秩處理同分的秩和 AUROC，與在每個置換後標籤向量上重算 ROC AUC 完全相同。
12. **嚴重度與擁擠。** 偵測計數使用合併的 oracle 閾值，並與同一群體的邊際標記率做單尾二項比較。這些為描述性結果：基準率是估計而得，且同一牛隻內的結果未必獨立。擁擠分層為未調整的合併比較，並非擁擠效應的因果估計。
13. **逐牛正規化。** 牛隻內 z 分數使用該牛出摺分數的母體標準差（ddof = 0）；僅一個通過段的牛隻保留原始分數，多通過段但變異數為零的牛隻得到零。分數四捨五入至 12 位小數，使兩通過段牛隻所產生的精確 +/-1 同分能在 CSV 往返後保留（未四捨五入時，浮點雜訊打破了同分，使記憶體內與存放值之間的 AUROC 不同）。此程序混合了不同尺度且為轉導式（transductive）；它是 Methods 所述的敏感度分析，並非經校準的部署方法。`unknown` 群組遵循所選的缺失 ID 策略。
14. **參考值。** `cowlame/manuscript_reference.json` 存放用於比較的稿件數值，每個區塊皆標註來源。精確的文字數值：PatchCore/Subspace AUROC 網格（腿部與全身）、PatchCore-CGI 區間、AUPRC、max-F1、置換統計量、Spearman rho 與各嚴重度中位數分數、偵測計數、擁擠分層、分析通過段數與分割 Table 1。自圖讀取（近似，約 +/-0.01）：ConvAE 與 STFPM 的 AUROC。文中僅約略陳述：HEI 置換帶、晚期融合與逐牛 AUROC。稿件的 Evaluation protocol 將每個報告的點估計界定為合併出摺分數上的指標，將每個報告的 95% 區間界定為跨五摺的 t 區間，因此每個稿件 AUROC 皆同時與此處所得的合併值及摺平均值比較，其中合併列才是同類比較。未報告：Subspace 輕度偵測計數；該列顯示 NA。已發表的非對稱 PatchCore 區間照原文複製。
15. **選用分析。** PatchCore 距離評估的成本夠低，因此除 Subspace 串接外，亦執行 GEI + CGI + FDEI patch 特徵串接（在對應 patch 位置上共 120 個通道）。每個模態在凍結特徵擷取前各自獨立做 ImageNet 正規化；未加入特徵加權或聯合正規化。圖表資料以 CSV 存放；不產生套用樣式的圖。
16. **硬體與環境。** 稿件列出 GTX 1080 8 GB、CUDA 11.8 與 PyTorch 2.5.1。此處存放的執行結果使用 RTX 5070 搭配 CUDA 12.8 的 PyTorch 建置版本；已安裝的版本逐字釘選於 `requirements.txt` 與 `environment.yml`，GPU/版本字串記錄於 `results/runtime_main.json`。在 Windows 上，`conda run` 需要在 `cowlame` 環境內設置一個 ASCII 暫存資料夾，因為其啟用批次檔無法處理非 ASCII 的儲存庫路徑。
17. **上游分割。** 封存的 `args.yaml` 記錄 `device: 0,1`、`split: val`、`tracker: botsort.yaml`、100 個 epoch 搭配 patience 25 與磁碟快取；這些訓練時期的設定本身不足以確立下游所用的單 GPU 或 ByteTrack 推論組態。封存的推論 notebook 執行單張影像預測，不含任何追蹤呼叫。資料集 YAML 帶有一個已過時的 Linux 絕對路徑 `path:`；僅儲存庫內的本地副本被重新對應到目前的絕對資料集根目錄。`val` 與 `test` 各自獨立評估（`docs/SEG_XCHECK.md`），所有輸出與快取皆限制於儲存庫內。
18. **能量影像參考實作。** `cowlame/energy_images.py` 自二值輪廓實作 Eq. (1) 至 (5)：質心對齊的 GEI、CGI 採等索引時間三等分、FDEI 為正向畫格差加上保留段落峰值的靜態能量（Methods 未給出數值去雜訊閾值；`EnergyConfig.denoise_peak_fraction` 將此選擇外顯），以及全身/前段/後段聯集對齊的 HEI 與六種通道排列。視窗 hop 未記錄於 `mask_meta.json`；`EnergyConfig.window_step`（預設 5）是一項外顯的假設。程式碼所採取的其他解讀：每個輪廓的前/後分割點為其逐畫格邊界框的中點；行進方向（`front_direction = "auto"`）由視窗中第一個與最後一個非空畫格之間淨質心位移的正負號推得，可以 `--front-direction` 覆寫；FDEI 差分的第一個前一畫格為第一個畫格本身（B_0 := B_1）；HEI 通道以 180 x 382 繪製以符合封存的 HEI PNG，GEI/CGI/FDEI 則為 220 x 318。產生封存影像的 MATLAB 形態學運算與身體比例裁切不屬於這些方程式，故不預期完全相同；一致性於 `docs/EI_XCHECK.md` 中逐視窗量化。
19. **與 Methods 文字的具名偏離：未重現身體比例裁切。** Methods 陳述步態能量影像依身體比例裁切並縮放至 220 x 318 像素。重建僅執行其後半部分：`cowlame/energy_images.py` 直接將未修剪的前景邊界框聯集縮放至封存的輸出尺寸。對 GEI、CGI 與 FDEI，該聯集取自質心對齊後的逐畫格框（`align_centroids`），並縮放至 `EnergyConfig.image_hw` = 220 x 318；HEI 未做質心對齊，故其全身/前段/後段通道取自視窗的原始逐畫格框，即沿動物行進軌跡的聯集，並縮放至 `EnergyConfig.hei_hw` = 180 x 382。不施加身體比例裁切，因為封存的中繼資料未記錄該規則（以哪個身體地標定義比例、保留多少比例、逐畫格或逐視窗施加），而猜測一個規則會把未記錄的自由參數放進參考實作中。這是重建相對於已發表 Methods 的偏離，而非上列的歧義解讀之一：身體比例裁切改變了填入固定輸出尺寸的視野範圍，因此它會重新縮放每張能量影像內的輪廓。故它可能與未記錄的 MATLAB 形態學運算及視窗 hop 一同，促成 `docs/EI_XCHECK.md` 所報告的再生成影像與封存影像間的不完全一致。偵測結果不受影響：每項分析皆讀取封存的 PNG，其已帶有原始裁切。
